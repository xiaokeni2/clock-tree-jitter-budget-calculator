Formulas

  • Jtotal = √( Jsrc² + Σi=1..N Jadd,i² )  (quadrature sum)
  • Stage contribution  pi = Jadd,i² / Jtotal² × 100 %
  • Source contribution psrc = Jsrc² / Jtotal² × 100 %
  • Budget margin = ( Jbudget − Jtotal ) / Jbudget × 100 %

Uncorrelated, random (Gaussian) jitter sources add as the square root of the sum of squared RMS values — variances add, RMS values do not. Deterministic jitter (SPUR, periodic jitter) must instead be added linearly or by the closed-form worst-case methods; this tool covers the random-RMS budget only. All inputs must use the same integration bandwidth.

Selection guidance — when to spend on low-additive-jitter distribution

  • Contributions are quadratic — attack the biggest square first. If one stage contributes more than ~50 % of Jtotal², replacing only that stage gives you nearly all of the possible improvement; cleaning up already-small stages buys almost nothing.
  • Many stages favor low-additive buffers. A tree with 6+ levels of distribution amplifies any per-stage penalty: 8 stages × 0.5 ps of additive jitter already add √8 × 0.5 ≈ 1.4 ps of RMS jitter by themselves. For deep trees, use buffer or retimer stages specified below ~0.2 ps.
  • PLL-based devices add more than passive-style fanout. Use no-PLL fanout buffers where you only need fanout and skew control; reserve PLL buffers, jitter cleaners and retimers for stages that must reject phase noise, break jitter accumulation or re-clock a dirty reference.
  • Keep the integration band consistent. A source quoted at 12 kHz–20 MHz cannot be combined with a buffer quoted at 1 kHz–20 MHz without re-integration; mismatched bands are the most common cause of optimistic budgets.
  • Leave margin. Keep 20–30 % of the budget unallocated for supply-noise degradation, PCB crosstalk and unit-to-unit spread over temperature.

FAQ

Why do RMS jitter values add in quadrature (square-root of sum of squares)?

Random Gaussian jitter from independent stages is uncorrelated, so the variances (σ²) of the contributions add. The total RMS value is therefore σ_total = √(Σσᵢ²). RMS jitter values themselves never add linearly — summing them directly overestimates the tree by a large margin, especially with many stages.

How do I convert RMS jitter to peak-to-peak jitter?

Peak-to-peak depends on the target BER through the crest factor: Jp-p ≈ 2 × N × JRMS, where N is set by the Gaussian tail probability (a common engineering value is N ≈ 7, i.e. Jp-p ≈ 14 × JRMS, corresponding to roughly 10⁻¹² BER). This tool works in RMS throughout; convert only at the final receiver decision threshold.

My datasheet quotes phase noise, not additive jitter — what now?

Convert the device's output phase noise to RMS jitter by integrating L(f) over the band of interest (single-sideband, offset decade by decade), then enter that residual value here. If you need that conversion, use a phase-noise-to-jitter tool such as the one linked in the footer before using this calculator.
